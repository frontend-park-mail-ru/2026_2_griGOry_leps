## Технологический стек

- **Язык:** TypeScript (ES-модули, без фреймворка)
- **Рендер:** собственный виртуальный DOM (`src/vdom`), разметка компонентов на JSX — см. [Как устроен VDOM](#как-устроен-vdom)
- **Стили:** SCSS (препроцессор Sass) и PostCSS с autoprefixer (постпроцессор), именование классов по БЭМ — см. [Стили](#стили)
- **Сборка:** [Vite](https://vitejs.dev/)
- **Раздача собранного фронта:** [Express](https://expressjs.com/) (`server.js`)
- **Линтеры:** ESLint для кода, Stylelint для стилей
- **Тесты:** [Vitest](https://vitest.dev/) + jsdom
- **Документация кода:** [TypeDoc](https://typedoc.org/)

## Как работать с задачами

Все задачи, фронтовые и бэковые, ведутся на одной [доске в YouGile](https://ru.yougile.com/team/82999ec3673c/GOSH4LEEPS).

> [!IMPORTANT]
> Название ветки и Pull Request всегда содержат номер задачи (`GOS-###`) —
> это единственное, что связывает код с задачей на доске, так как задача
> и репозиторий живут в разных системах.

1. **Взять задачу.** На доске в YouGile выбрать задачу, назначить на себя, отметить, что взяли в работу

2. **Создать ветку** от `main` с именем `GOS-###`, где `###` — номер задачи:

   ```bash
   git checkout main && git pull
   git checkout -b GOS-12
   ```

3. **Закоммитить** по шаблону `<тип>: <описание>`, типы — в таблице ниже.
   Область в скобках после типа указывать необязательно:

   ```
   feat: добавить форму входа
   fix: не сбрасывать фокус при ошибке валидации
   refactor(router): вынести обработку ссылок в отдельный модуль
   ```

4. **Открыть Pull Request** в `main`, когда код готов к ревью.
   Заголовок — по шаблону `GOS-###: description`, например `GOS-12: Форма входа`.
   В описании PR — ссылка на задачу в YouGile

5. **Получить апрув** от тимлида/ментора

6. **Влить в `main`** через Merge, задачу в YouGile перевести в «Готово» вручную

## Типы коммитов

> [!NOTE]
> Коммиты ветки попадают в `main` как есть, поэтому от их качества зависит
> читаемость истории проекта. Сверху добавляется merge-коммит с названием Pull Request

| Тип | Когда используется |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `refactor` | код переписан, поведение не изменилось |
| `style` | форматирование и отступы, логика не тронута |
| `test` | тесты |
| `docs` | документация |
| `chore` | конфиги, зависимости, сборка, CI |

## Установка и запуск проекта

### Системные требования

- [Node.js](https://nodejs.org/) 20.11+ (LTS)
- npm (ставится вместе с Node.js)
- запущенный бэкенд (см. [README бэкенда](https://github.com/go-park-mail-ru/2026_2_griGOry_leps))

### Пошаговая инструкция

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/frontend-park-mail-ru/2026_2_griGOry_leps.git
   cd 2026_2_griGOry_leps
   ```

2. Создайте локальный файл окружения:

   ```bash
   cp .env.example .env
   ```

   `VITE_API_URL` — адрес API бэкенда, по умолчанию `http://localhost:8080/api`.

3. Установите зависимости:

   ```bash
   npm install
   ```

4. Запустите dev-сервер:

   ```bash
   npm run dev
   ```

Приложение будет доступно на `http://localhost:5173`. Бэкенд должен быть запущен на `http://localhost:8080`, а в его `.env` — `FRONTEND_ORIGIN=http://localhost:5173`, иначе браузер заблокирует запросы по CORS.

### Сборка и запуск как на сервере

```bash
npm run build
npm start
```

Express раздаёт собранный фронт из `dist/` на `http://localhost:8001` (порт меняется переменной `PORT`). В этом режиме в `.env` бэкенда должно быть `FRONTEND_ORIGIN=http://localhost:8001`. Адрес API вшивается в сборку, поэтому после изменения `.env` нужно пересобрать проект.

### Скрипты

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер Vite с горячей перезагрузкой |
| `npm run build` | проверка типов и сборка в `dist/` |
| `npm run typecheck` | только проверка типов (`tsc`) |
| `npm start` | раздача `dist/` через Express |
| `npm run lint` | проверка кода ESLint |
| `npm run lint:fix` | автоисправление ошибок ESLint |
| `npm run lint:css` | проверка стилей Stylelint, в том числе нейминга по БЭМ |
| `npm run lint:css:fix` | автоисправление ошибок Stylelint |
| `npm test` | юнит-тесты (Vitest) |
| `npm run docs` | генерация документации в `docs/` |

## Стили

Стили пишутся на SCSS. При сборке Sass превращает их в CSS, затем PostCSS с autoprefixer дописывает браузерные префиксы по списку `browserslist` из `package.json`, поэтому префиксы вручную не пишем.

Правила:

- у каждого компонента и страницы свой `.scss` рядом с `.tsx`, в нём один блок с именем как у папки;
- классы только по БЭМ: `блок`, `блок__элемент`, `блок--модификатор`, `блок__элемент--модификатор`, слова через дефис;
- элементы не вкладываются друг в друга по имени: `card__title`, а не `card__head__title`;
- в селекторах компонентов нет тегов, id и `*` — нужному тегу даём класс-элемент;
- блок не стилизует другие блоки изнутри: если соседнему блоку нужен другой вид, у него появляется модификатор;
- цвета, отступы и шрифты берём из `src/shared/styles/_variables.scss` и `_mixins.scss`;
- теги стилизуются только в базовых стилях `src/app/styles`.

Сброс в `_reset.scss` обнуляет отступы у заголовков, абзацев и списков с классом, поэтому нужные отступы задаём в стилях элемента явно.

Правила проверяет `npm run lint:css` — локально и в CI.

## Как устроен VDOM

Страницы и компоненты описываются на JSX в файлах `.tsx`. JSX компилируется в вызовы `jsx()`
из `src/vdom/jsx-runtime.ts`, импорт подставляется в каждый `.tsx` автоматически
(`jsxImportSource` в `tsconfig.json` и `vite.config.js`).

```
src/vdom/
  h.ts               виртуальные узлы: h(), Fragment
  jsx-runtime.ts     во что компилируется JSX, типы для JSX
  props.ts           атрибуты, свойства (value, checked) и обработчики событий
  render.ts          render(container, vnode): сравнение деревьев (diff) и точечные изменения DOM (patch)
  component.ts       Component<Props, State> — компонент с состоянием и setState
  vdom.test.tsx      юнит-тесты
```

- **Функциональный компонент** — функция от пропсов, состояния нет: `const Card = ({ title }: { title: string }) => <h3>{title}</h3>`.
- **Классовый компонент** — наследник `Component` с `state` и `setState()`. При `setState` перерисовывается
  только он сам. Есть `componentDidMount()` и `componentWillUnmount()` для подписок.
- **Списки** — передавайте `key`: `items.map((item) => <li key={item.id}>…</li>)`, тогда при перестановке
  элементы переиспользуются, а не создаются заново.
- **События** — `onClick`, `onInput`, `onSubmit` и т. д.; `onChange` у поля ввода срабатывает,
  когда пользователь закончил ввод и ушёл из поля (как нативное событие `change`).
- **Доступ к DOM-элементу** — `ref={(el) => { this.el = el; }}`.

Приложение рисуется одним деревом в `src/app/main.tsx`: `render(app, [<Header />, <main>{страница}</main>, <Footer />])`.
При переходе по страницам или входе/выходе пользователя VDOM меняет в DOM только отличия.
